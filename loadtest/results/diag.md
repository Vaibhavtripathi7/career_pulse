## Workload

- **100,000 unique synthetic messages** across 1,000 users (100 each), plus **5,000 exact duplicates** (same ID, same content) = **105,000 Gmail deliveries per run**.
- 10,000 job-application emails (10%) and 90,000 promo/other emails, from 17 templates. Message IDs are stable 16-hex strings.
- One BullMQ job per user, which is production's unit of work (`fetchemails(userId)`): 1,000 jobs per run. Each worker process runs production's worker unchanged, with concurrency 2.
- Production code is not modified. `googleapis` and the Gemini fallback are swapped for local fakes by ESM resolve hooks, and any non-loopback TCP connection is refused. `NODE_ENV=production`: pino JSON logs at info (to /dev/null) and Postgres over TLS.
- **Oracle:** the production parser, run over every unique message, accepts **9,875** of them, so that is the exact row count a complete sync must produce. It stores 9,875 of 10,000 job emails and 0 of 90,000 promos. It predicts **283 LLM-fallback calls per pass** (265 unique messages, re-parsed when duplicated).
- **Single-threaded pipeline cost** (parser + body extraction, no queue or database): 47 µs per message, 21,242 msgs/s. Generating the synthetic source costs another 26 µs per delivery, which the workers also pay.

- Messages/s counts every Gmail delivery a worker fetched and processed (105,000 per run), divided by the queue drain time (first enqueue to last job finished). Each run's processed-delivery count was checked against that total.
- **Exact** latency is BullMQ's `finishedOn - processedOn` for each of the 1,000 jobs: one user's whole sync. The **histogram** columns apply PromQL's `histogram_quantile` algorithm to production's existing `email_sync_duration_seconds` metric, scraped from every worker. Its lowest bucket is 0.5 s, so it cannot resolve faster syncs: see the analysis.
- "Rows match oracle" means the database held exactly the oracle's (user, message) set (no missing, no extra, no duplicate rows), every delivery was processed, the LLM stub count equalled the oracle's prediction, and no job failed.
