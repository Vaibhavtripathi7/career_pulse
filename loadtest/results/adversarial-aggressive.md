## Workload

- **5,000 unique synthetic messages** across 50 users (100 each), plus **250 exact duplicates** (same ID, same content) = **5,250 Gmail deliveries per run**.
- 500 job-application emails (10%) and 4,500 promo/other emails, from 17 templates. Message IDs are stable 16-hex strings.
- One BullMQ job per user, which is production's unit of work (`fetchemails(userId)`): 50 jobs per run. Each worker process runs production's worker unchanged, with concurrency 2.
- Production code is not modified. `googleapis` and the Gemini fallback are swapped for local fakes by ESM resolve hooks, and any non-loopback TCP connection is refused. `NODE_ENV=production`: pino JSON logs at info (to /dev/null) and Postgres over TLS.
- **Oracle:** the production parser, run over every unique message, accepts **489** of them, so that is the exact row count a complete sync must produce. It stores 489 of 500 job emails and 0 of 4,500 promos. It predicts **12 LLM-fallback calls per pass** (11 unique messages, re-parsed when duplicated).
- **Single-threaded pipeline cost** (parser + body extraction, no queue or database): 57 µs per message, 17,550 msgs/s. Generating the synthetic source costs another 31 µs per delivery, which the workers also pay.
